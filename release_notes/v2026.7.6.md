## Highlights

2026.7.6 is an in-month bug-fix patch that back-ports three fixes from the August development line to the 2026.7.x stable series, each re-implemented against this line's code. It stops a resting cover from being wrongly re-closed after an integration reload (#1022), keeps covers from fail-opening to their default position when a custom-position sensor briefly drops out (#1005), ends a false manual-override that could fire mid-flight during venetian tilt (#1006), and fixes the Building Profile "Shared sensors" step closing the whole options dialog instead of returning to the menu (#1003). No configuration changes and nothing to migrate.

## Fixed

- **Manual-override command target survives an integration reload (#1022):** After a reload the in-memory command-target store rebuilt empty, so a resting cover had `has_recorded_target=False`. A context-less physical-remote move was then forced through the guard-less no-target rescue branch and wrongly rejected — re-closing a door cover. `CoverCommandService` now rehydrates its target from the existing `position_verification` sensor via the `RestoreEntity` pattern, so `has_recorded_target` is `True` again after a reload and the move takes the fully-guarded normal detection path. The restored target equals the resting position (no command is issued) and is never safety-tagged.

- **Custom-position slot holds through a transient unavailable sensor (#1005):** `read_custom_position_sensors` coerced `unavailable`/`unknown`/missing to the same `False` as a valid off. A brief sensor dropout — for example during a `template.reload` — flipped a slot `is_on` `True→False`, deactivated the pipeline handler, and fired a false active→inactive release edge that force-dispatched every cover to its default position (a fail-open). The builder now distinguishes a valid off from a no-usable-value read: it reads activation via `get_safe_state` plus a tri-state template render, derives a per-slot `is_valid`, and on an invalid read holds the slot's last-valid activation from a per-instance cache in `PipelineSnapshotBuilder`. A literal off is still a valid release; only `unavailable`/`unknown`/missing is held.

- **Venetian tilt override anchored to the dispatched tilt (#1006):** A handler reevaluation mid-flight re-anchored the expected tilt from a freshly recomputed pipeline result while ACP's own `open_cover` was still travelling and had dispatched no replacement. The actuator settling at the commanded tilt then no longer matched the reevaluated expectation and was misclassified as a manual override. The secondary-axis tilt expectation is now sourced from the tilt ACP last dispatched (`sequencer.last_tilt_target`) via a shared `resolve_dispatched_secondary_expected` helper the venetian policy delegates to. When ACP dispatched no independent tilt (tilt-skip suppress, restart, drift-verify pop, Auto-Control re-enable) the check asserts no tilt expectation rather than falling back to the reevaluated pipeline tilt. The value-based excursion suppression (#927) and the position axis are unaffected.

- **Building Profile "Shared sensors" step returns to the menu on submit (#1003):** The step called `async_create_entry()` on submit — HA's flow-terminal call — which closed the whole options dialog instead of returning to the profile menu where "Done" (save & close) lives. It now returns to `async_step_init` on submit, matching every other options sub-step.
