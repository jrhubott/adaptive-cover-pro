## Highlights

2026.9.1 is a two-fix patch: the "Return to default when disabled" switch is now available on tilt and louvered-roof covers, and a new opt-in option lets the operating window wait for sunrise before it opens. Both land behind settings that default to off, so an install that doesn't touch either one sees no change in behavior.

## Fixed

**The return-to-default switch now appears on tilt and louvered-roof covers (#1349):** `supports_return_to_default_switch` excluded every tilt-primary cover type on the theory that only position-axis covers have a meaningful default height, but the dispatch it gates already routes correctly to whichever axis the policy owns — the switch's one configured value travels through `apply_position`, and `select_default_axis` sends it down the tilt axis for a tilt-primary cover exactly the way the climate handler already does every cycle. `TiltPolicy` and `LouveredRoofPolicy` now opt in, so the switch entity is created for those cover types where it wasn't before; like every other cover type, it starts off. Multi-axis policies (venetian, day/night shade) stay excluded — enabling either would feed a stale previous-cycle tilt into the same dispatch path, reintroducing the defect class issue #684 fixed — and a new registry-driven test locks that exclusion in place.

**The operating window can now wait for sunrise before it opens (#1340):** With a configured start time earlier than sunrise, the window opened — and the night position ended — right at that configured start, ignoring the Sunrise Time Entity and Sunrise Offset entirely, even though the shipped description promised the later of the two would win and the position forecast already behaved that way. A new opt-in `sunrise_gates_start` option floors the window's effective start at the resolved sunrise boundary, threaded through `TimeWindowManager._resolve_start_datetime` so every start-derived check — including the night position — agrees. It defaults to off: issue #438 is the decision of record for the original behavior, and every existing install keeps it unless the new option is turned on.

## Upgrade notes

Upgrading changes nothing on its own. This release's config-entry migration only advances entries from minor version 21 to 22; it's additive and seeds no keys, so `sunrise_gates_start` reads as off — today's behavior — on every existing entry. The return-to-default switch newly exists on tilt and louvered-roof covers, but like every cover type it's created off, so nothing starts moving until you enable it.

## Compatibility

Home Assistant 2026.3.0+ and Python 3.11+. The config entry's major version is unchanged at 3, and `MINOR_VERSION` reaches 22 — additive and rollback-safe, so rolling back to an older stable finds an existing configuration exactly as it left it. The companion Lovelace card ([jrhubott/adaptive-cover-pro-card](https://github.com/jrhubott/adaptive-cover-pro-card)) is on its own release cycle and needs no update for this release.
