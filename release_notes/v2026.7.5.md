## Highlights

2026.7.5 fixes a venetian tilt_only + endpoint_use_open_close regression: the `sun_just_appeared` re-confirm bypassed the same-position gate in `apply_position()` and re-fired `close_cover` against a carriage already parked at a mechanical endpoint (#985). On Somfy-style covers that resend also drove the slats shut, a real physical disturbance the integration then had to reverse on the next cycle. No configuration changes and nothing to migrate.

## Fixed

- **Venetian sun-appeared re-confirm no longer resends at a mechanical endpoint (#985, #986, #987):** In venetian tilt_only + endpoint_use_open_close, the `sun_just_appeared` sentinel — set on the default→solar FOV-entry transition — bypassed the same-position gate in `apply_position()` and re-fired `close_cover` for a carriage already parked at 0%. On Somfy blinds `close_cover` also drives the slats shut, so the unchanged 0/50 target caused a 50→0 tilt disturbance that Adaptive Cover Pro then had to restore.

  I scoped the `sun_just_appeared` re-confirm so it no longer applies when the target is a hard mechanical endpoint (`POSITION_CLOSED`/`POSITION_OPEN`) the cover already occupies, mirroring the idempotency the `force_endpoint` channel already respects via `_is_at_mechanical_stop`. The new `sun_reconfirm` gate falls into the existing same-position skip branch, which still services the tilt axis, so the #770/#775 forced-tilt behavior and #779 no-feedback re-confirm are preserved.
